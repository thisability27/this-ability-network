# 커밋 작성 및 검토

1. 저장소 루트, 현재 브랜치, 작업 트리, 스테이징 상태, 최근 커밋을 확인합니다. 관련 변경을 목적별로 묶고 기존 스테이징과 관련 없는 변경을 보존합니다.
2. 제목은 `type(domain): 한글 제목` 형식으로 작성합니다. `type`과 `domain`은 영문 소문자 식별자를 사용하고, 여러 단어는 하이픈으로 연결합니다. Gitmoji 접두사는 사용하지 않습니다. 본문이 필요하면 빈 줄 뒤에 변경 이유와 검증 결과를 한글로 적습니다.
3. 커밋할 경우 관련 경로만 스테이징하고 `git diff --cached --check`와 스테이징된 내용을 검토합니다. 메시지 파일이 있다면 `node .agents/skills/git-commit-helper/scripts/validate-commit-message.mjs <메시지-파일>`로 제목 형식을 확인합니다. 본문의 언어와 내용은 직접 검토합니다.
4. 요청 범위에서 커밋하고 해시와 포함된 파일을 확인합니다. 푸시와 이력 재작성에는 별도 요청이 필요합니다.

```text
refactor(assets): HTML에 내장된 이미지를 원본 파일로 분리

전달받은 HTML에서 JPEG를 추출하고 상대 경로로 참조합니다.
```
